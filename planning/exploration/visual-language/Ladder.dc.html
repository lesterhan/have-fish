The contrast ladder — warm graphite

One rule fixes most of the critique: an element occupies the same rung in both themes. Surfaces step by apparent lightness — OKLCH ΔL, because at the dark end a perceptually equal step produces a tiny WCAG ratio, which is exactly why today's dark theme reads flat. Ink keeps the ratio contract. Both are assertable in tokens.test.ts against the token file, the same way the coverage strip already is.

The assertions that hold it

// surfaces: adjacent rungs step by apparent lightness, and by a comparable
// amount in both themes — the dark end needs a slightly larger step to look equal.
for (const [a, b, lo, hi] of SURFACE_STEPS) {
  expect(deltaL(light[a], light[b])).toBeWithin(lo, hi)
  expect(deltaL(dark[a],  dark[b] )).toBeWithin(lo, hi)
  // and neither theme may be more than 2x the other on the same step
  expect(ratioOfSteps(a, b)).toBeLessThan(2)
}

// ink: every rung clears 4.5:1 on its panel in BOTH themes, and the two
// halves of an opposed pair land within 25% of each other.
expect(contrast('--color-amount-negative', '--surface-panel')).toBeGreaterThan(4.5)
expect(spread('--color-amount-positive', '--color-amount-negative')).toBeLessThan(1.25)

Six accents × two themes still has to survive this: the accent rung is the only one a user can move, so it is asserted per accent rather than once. That is twelve assertions the token file can carry, and it is cheaper than finding out in a screenshot.
